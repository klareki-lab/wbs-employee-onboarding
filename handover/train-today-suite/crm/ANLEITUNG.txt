PRÄMIENBEISPIEL (KONFIGURIERBARE ÜBUNGSREGEL, KEINE FERTIGE LOHNRICHTLINIE)

Realisierte Marge je nicht storniertem Auftrag:
  max(Auftragswert - Kosten, 0) x min(Nettozahlung / Auftragswert, 1)
Nettozahlung = Zahlung abzüglich Erstattung, mindestens 0.
Prämientopf = realisierte Marge x konfigurierter Prozentsatz.
Beispiel: 10 % Topf; 30 % Erstkontakt, 20 % Qualifizierung, 50 % Abschluss.
Fehlende Beiträge und Rundungsreste bleiben als „unverteilt“ sichtbar.
Neue Abrechnung = aktueller Anspruch minus bereits freigegebene Beträge je Person.
Die Geschäftsführung entscheidet; es gibt keine automatische Lohnauszahlung.
Der Lead-Score aus Sergiis Kern ist ausdrücklich keine Prämiengrundlage.

TECHNISCHE RECHTE

crm_owner     besitzt die lokalen CRM- und Kernobjekte; nur Einrichtung/Migration.
crm_app       beschränkte Anwendungsrolle; keine Schemaänderung, keine Audit-Änderung.
crm_agent     nur lesende Datenrechte; keine Anmeldungstabellen, keine Schreibrechte.
crm_capture   Sergiis Capture-Rolle nach seinem Grant-Skript.
crm_worker    Sergiis Worker-/E-Mail-Funktionsrechte.
crm_status    Sergiis eingeschränkte Status-Funktionsrechte.
crm_operator  gesonderte Betriebs-/Wiederholungsrechte; nicht im Frontend.

Das zusätzliche Schema crm enthält persönliche Konten, Sitzungen, typisierte Datensätze,
Projektbeteiligungen, unveränderlichen Verlauf, Wiederholungsschutz und eine Outbox.
Datensatzrechte gelten auch in PostgreSQL. Der Benutzerkontext ist serverseitig signiert;
die Agent-Rolle kann sich durch SET crm.actor_id keine andere Identität geben.
Alle fachlichen Änderungen erfolgen in Transaktionen, Eingaben als SQL-Parameter.
Nur der vertrauenswürdige CRM-Dienst erhält INTERNAL_KEY und die Schreibverbindung.
Der Agent bekommt ausschließlich die getrennte Leseverbindung bzw. den Lese-Endpunkt.

NEU AUFBAUEN

Voraussetzungen: Docker Desktop und Node.js 22+.
Die ZIP-Datei enthält keine lokalen Passwörter und keine bestehenden Docker-Volumes.
In einem neuen Ordner:
  node src/setup.mjs
  docker compose --profile local-core up -d --build
  node src/local-core-setup.mjs
  docker compose up -d app
  docker compose exec -T app node src/seed.mjs
  docker compose exec -T app node src/repair-demo.mjs

Die lokale n8n-Testinstanz verwendet das auf diesem Rechner vorhandene Image
n8nio/n8n:2.40.7-09b3ce6-pc. Für einen anderen Rechner ein verfügbares, kompatibles
n8n-Image in compose.yaml wählen und den Integrationstest dort wiederholen.
SQL-Dateien werden beim ersten leeren PostgreSQL-Volume automatisch in Namensreihenfolge
ausgeführt. Bei bestehendem Volume werden neue SQL-Dateien nicht automatisch nachgezogen.
